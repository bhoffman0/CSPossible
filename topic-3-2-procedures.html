    Section 3.2 Procedures (Functions)

    135 minutes
    Quick Links: 3.2.1, 3.2.2, 3.2.3, 3.2.4, 3.2.5, 3.2.6, 3.2.7, 3.2.8, 3.2.9, 3.2.10
    🔗
    Our programs are getting longer and longer! Advanced programmers break up large programs into smaller, more manageable pieces called procedures or functions. This allows programmers to solve complex problems by breaking them into smaller subproblems and to reuse code. In this lesson, we will learn to write our own Python functions and learn how procedural abstraction helps manage complexity.
    🔗

    Subsection 3.2.1 What is a Procedure or Function

    Essential Knowledge 3.2.1. 3.2.A.1.

    A procedure is a named group of programming instructions that performs a task. Using procedures helps programmers organize code, avoid unnecessary code, and make programs easier to read, test, and update. Procedures may also be called functions or methods depending on the programming language.
    🔗
    🔗
    A procedure or function is a named block of code that performs a task when it is called.
    🔗
    We have already used several built-in Python functions in our programs, for example input() and print() which are input/output functions built into Python. Notice that functions end with parentheses () which can contain arguments, the data that the function needs to do its job, for example what to print for the print("Print this!") function. Some functions like input() or random.randint() also return values back like the user’s input or a random number that we usually store in a variable.
    🔗
    A function is like a black box where you know what data goes in and what data comes out, but not necessarily how it works inside. We don’t really need to know exactly how print() or input() works internally; we just need to know what it does. This is called procedural abstraction where the code is grouped into manageable chunks called procedures or functions that can be called by name, hiding the detailed implementation steps from the rest of the program. This allows programs to be more complex without being overwhelming. Here are some of the Python functions that we have used so far.
    🔗
    # The print() function takes 1 argument that it prints to the screen
print("Hello World!")  

# The input() function takes 1 argument, the prompt, and returns the user's input
#     which we save in a variable
name = input("Enter your name: ")

# The random.randint() function takes 2 arguments, the low and high values, 
# and returns a random number between those values (inclusive)
random_number = random.randint(1, 10)

    Subsection 3.2.2 Procedure/Function Calls and Definitions

    Let’s learn how to define our own functions and call them to do their jobs! The main reasons to divide up a program into multiple functions are to organize the code to reduce its complexity and to avoid repetition of code. For example, the "This Old Man" song below has a lot of repetition (listen here). Instead of writing the same code over and over in order to print the song, we can write functions for different parts of the song and run them when needed. Click on all lines of code that are repeated in the song below, and then we will learn how they can be replaced with a function called chorus().

print("With a knick-knack paddywhack, give a dog a bone,")
print("This old man came rolling home.")
    🔗
    There are two steps to writing a function: the function definition and the function call. A function in Python is defined by using the keyword def followed by the function name which the programmer chooses. Indented inside the function, we write the code that will be executed when the function is called. We can call a function or procedure by using its name, for example chorus(). Functions always have parentheses () after their name even if it’s empty parentheses. In Python, functions always have to be defined before they can be called, so programmers put the function definitions at the top of the program and the main program below.
    🔗
    # Function definition
def functionName():
    <block of statements>

# Function call
functionName()
    In AP CSP pseudocode, functions are called procedures, and the keyword procedure is used instead of def to define a function. Curly braces are used to enclose the block of statements, instead of just indentation. Procedure calls just use the name of the procedure with parentheses like in Python.
    🔗
    # AP pseudocode procedure definition
procedure procName()
{
    <block of statements>
}

# AP pseudocode procedure call
procName()

    Essential Knowledge 3.2.2. 3.2.B.1.

    Calling a procedure runs a named sequence of steps, which helps programs reuse code and keep the overall program easier to read and follow.
    🔗
    🔗

    Essential Knowledge 3.2.3. 3.2.B.2.

    A procedure is called by using its name in a statement so the program runs the steps stored in that procedure. When the call happens, the program pauses the current sequence of statements, executes the procedure’s instructions, and then resumes at the next statement after the call.
    🔗
    🔗
    When a function is called to do its job, the computer jumps to the function definition and runs the code inside it. When the function is finished, the computer jumps back to the line after the function call and continues running the program.     Subsection 3.2.3 Arguments and Parameters

    Essential Knowledge 3.2.6. 3.2.A.3.

    Procedures can use parameters to receive input. A parameter is a variable name listed in the procedure definition. An argument is the actual value provided when the procedure is called.
    🔗
    🔗
    Let’s take another look at the "This Old Man" song and see if we can replace more repeated code. Each verse of the song is similar except it uses a different number and rhyme. If we can pull these out into variables, we can write a single function that can print any verse of the song! Click on the words that are different in the lines that are repeated to discover what variables we need to add to the functions.
    🔗

    Activity 3.2.8.

    Click on the words that are different in the repeated lines.
    🔗
    Look for lines that are similar except for a different number or action and click on those words.
    print("This old man, he played one.")
print("He played knick-knack on my thumb.")
print("With a knick-knack paddywhack, give a dog a bone,")
print("This old man came rolling home.")
print("This old man, he played two.")
print("He played knick-knack on my shoe.")
print("With a knick-knack paddywhack, give a dog a bone,")
print("This old man came rolling home.")
    🔗
    We can make functions even more powerful and more abstract by giving them parameters for the data that they need to do their job. A parameter is a variable listed in the definition of a function and can be used inside the function body. This allows values, called arguments, to be passed into the function. The argument value is copied into the corresponding parameter variable. Many people use the terms "parameter" and "argument" interchangeably, but formally, the parameter is the variable in the function definition and the argument is the value passed to the function when it is called.
    🔗
    For example, here is a procedure called forward with a parameter variable called pixels that we used with turtles with procedure calls like forward(40) telling it to move forward 40 pixels. The value 40 is the argument that is passed to the parameter variable pixels in the procedure definition.
    🔗
    Going back to our song, we can make a function called verse that takes the number and the rhyme as parameters and uses them to print any verse! The parameter variables number and rhyme will hold different values each time the function is called.
    🔗
    # This function prints a verse for a given number and rhyme. 
# @param number - the number used in the verse 
# @param rhyme - the word that rhymes with the number

def verse(number, rhyme):
    print("This old man, he played", number, ".")
    print("He played knick-knack on my", rhyme, ".")
    chorus()
    The verse function can now be used to print any verse of the song. The values passed to the function become the values of the parameter variables. The main part of the program can be just calls to the verse function. Main program code often looks like an outline for the program, calling all the functions to do the work.
    🔗
    verse("one", "thumb")
verse("two", "shoe")
    Notice that the same function is called two times with different arguments. When verse("one", "thumb") is called, the parameter number gets the value "one" and the parameter rhyme gets the value "thumb". When verse("two", "shoe") is called, the same parameters receive different values. The function does not need to change. The arguments provide the values that make each verse different.
    🔗

    Let’s add one more abstraction! Let’s add data abstraction using lists along with procedural abstraction. We can create two parallel lists of the number and rhyme values and iterate through them. This abstraction makes our code even more flexible and makes it even easier to add another verse by just adding a new element to each list.
    🔗
    numbers = ["one", "two", "three"]
rhymes = ["thumb", "shoe", "knee"]
# Iterate through the lists and call verse() for each number and rhyme
for i in range(len(numbers)):
    verse(numbers[i], rhymes[i])

    Essential Knowledge 3.2.7. 3.2.A.4.

    A procedure may not need parameters when it always performs the same steps with no changing input (for example, displaying an instructions screen or resetting a game to a default starting state). Procedures need parameters when they need input information to complete the intended task. If a procedure should work for many different inputs (for example, greeting different users or calculating totals for different numbers), parameters make it flexible and reusable because the program can pass different arguments each time it is called. Using parameters when input varies helps avoid duplicating code and keeps the program easier to update.
    🔗
    🔗

    Essential Knowledge 3.2.8. 3.2.A.5.

    Procedures with parameters make it easier to adapt an app’s behavior or output to different users and situations without rewriting code. A single procedure with parameters can generate many clear, personalized messages for different users by using different argument values each time it is called.

    Subsection 3.2.4 Return Values

    Some procedures or functions also return a value back to the code that called them. For example, we have used the Python built-in input() function, which returns the user’s input as a string, and the random.randint() function, which returns a random integer. You can imagine a function as a calculating machine that takes numbers as arguments and returns a calculated result, or like a toaster that takes bread as an argument and returns toast.
    🔗
    When writing your own functions, you can use the keyword return to return a variable or value or expression. If you do not have a return statement in your function, Python automatically returns the special value None by default. So, all Python functions actually return a value, even if it’s just None. The return statement also immediately ends the function, so any code after the return statement is not executed.
    🔗

    Essential Knowledge 3.2.13. 3.2.A.7.

    Some procedures use a return statement to send a result back to the part of the program that called the procedure, which allows the returned value to be stored in a variable, used in an expression, or displayed as output. The return statement ends the procedure immediately, even if more statements appear later in the procedure. When the following code runs in the body of a procedure, the value of expression is returned to the place in the program where the procedure was called.
    🔗
    return expression
    🔗

    Essential Knowledge 3.2.14. 3.2.A.8.

    Some procedures perform an action, such as displaying output or updating variables, and do not return a value. Other procedures compute a value and use a return statement so the result can be used elsewhere in the program.

    Subsection 3.2.5 Procedural Abstraction

    Procedural abstraction means using functions or procedures in order to manage complexity in a program. It allows programmers to use a procedure and not worry about the details of how it exactly works (i.e. abstracting away the details and treating it as a black box).
    🔗

    Essential Knowledge 3.2.16. 3.2.C.1.

    Procedural abstraction manages complexity by grouping related code into named procedures that can be called from other parts of a program.
    🔗
    🔗

    Essential Knowledge 3.2.17. 3.2.C.2.

    Procedural abstraction allows programmers to use a procedure by knowing what it does without needing to know how it works internally. Programmers often use built-in procedures, such as print or random, by relying on the procedure’s name, purpose, and expected behavior while the implementation details stay hidden.
    🔗
    🔗

    Essential Knowledge 3.2.18. 3.2.C.3.

    Procedural abstraction helps manage complexity by breaking a large problem into smaller subproblems and creating procedures to solve each part.
    🔗
    🔗
    Modularity means dividing a program into smaller independent parts. Each part does one specific job. This is a great way to manage complexity because it divides the problem into more manageable parts that make it easier to design, test, and maintain. It also makes the code easier to understand.
    🔗

    Essential Knowledge 3.2.19. 3.2.C.4.

    The subdivision of a program into smaller, independent procedures or components is called modularity. Modularity helps programmers focus on one part at a time and makes programs easier to build, test, and revise.
    🔗
    🔗

    Essential Knowledge 3.2.20. 3.2.C.8.

    Using procedural abstraction improves readability because the rest of the program can call procedures with descriptive names, so the overall steps of the program are easier to understand at a glance.
    🔗
    🔗
    Procedural abstraction also removes repetition in code because it allows programmers to define a procedure once and then call it multiple times, rather than writing the same code repeatedly. This allows for code reuse and makes the code easier to maintain. If a change is needed, it can be made in one place instead of multiple places. In the following activities, we will refactor existing code by creating reusable functions. Remember that refactoring means making changes to the code’s structure without changing what it does.
    🔗

    Essential Knowledge 3.2.21. 3.2.C.5.

    Procedural abstraction supports code reuse by extracting shared behavior into a single procedure instead of duplicating code in multiple places.
