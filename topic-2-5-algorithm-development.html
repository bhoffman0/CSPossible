    🔗
    In this lesson, we will practive developing and comparing algorithms using repetition and selection. We will learn some common algorithms and patterns using loops that can be used to solve problems, for example calculating the sum or average of a group of numbers or finding the maximum or minimum value in a group of numbers.
    🔗

    Subsection 2.5.1 Developing Algorithms

    Essential Knowledge 2.5.1. 2.5.A.1.

    Algorithm use sequencing, selection, and iteration to organize steps, choose actions based on conditions, and repeat actions.
    🔗
    🔗
    The building blocks of algorithms are sequencing, selection, and repetition. With these three control structures, almost any problem can be solved.
    🔗

    Essential Knowledge 2.5.2. 2.5.A.2.

    Programmers can develop an algorithm from scratch, or they can reuse, combine, or adapt existing algorithms to solve a problem.
    🔗
    🔗

    Essential Knowledge 2.5.3. 2.5.A.3.

    Programmers often build new algorithms by reusing parts of known algorithms and adjusting them to fit a new problem, such as handling different inputs or producing a different output. They test the updated algorithm to confirm it meets its requirements.
    🔗
    🔗

    Subsection 2.5.2 Common Algorithms

    Essential Knowledge 2.5.4. 2.5.A.4.

    Knowing common algorithms and patterns can make problem solving more efficient. Many algorithms reuse common patterns, such as:
    🔗
    • computing the sum or average of values
      🔗
    • finding the maximum or minimum value in a group of numbers
      🔗
    • checking whether one integer is evenly divisible by another
      🔗
    🔗

    Subsubsection 2.5.2.1 Sum and Average Accumulator Algorithms

    One common algorithm is to compute the sum or average of a set of numbers. This is called the accumulator pattern; it uses a loop and an accumulator variable to keep track of the running total as each number is added. The accumulator pattern has 4 steps:
    🔗
    1. Initialize the accumulator variable before the loop.
      🔗
      🔗
    2. Loop through the values.
      🔗
      🔗
    3. Update the accumulator variable inside the loop.
      🔗
      🔗
    4. Print or use the accumulated value when the loop is done.
      🔗
      🔗
    🔗
    For example, this loop calculates the sum of 0 through 100 using range(101) since this generates numbers up to 101 but not including 101. The sum variable is the accumulator variable and number is added into the sum each time through the loop. Then, the average is calculated by dividing the sum by the number of values.
    🔗
    sum = 0
for number in range(101):
    sum += number
print("The sum of 0 through 100 is", sum)
average = sum / 100
print("The average of 0 through 100 is", average)

    Subsection 2.5.3 Comparing Algorithms

    Essential Knowledge 2.5.7. 2.5.B.1.

    There is often more than one way to solve a task. Different algorithms can use different steps, yet still produce the same output for the same inputs. By comparing algorithms, programmers can decide which approach is clearer, easier to maintain, or better suited to the situation.
    🔗
    🔗
    A problem can be solved with different algorithms. A simple example is the problem of calculating the sum of a list of numbers. We can use for loop or a while loop which look very different to solve the same problem. Compare the two algorithms below. Do they produce the same output?

    Loops can often be written in different ways and still be equivalent. A for loop that repeats a fixed number of times can often be rewritten as a while loop that uses a counter variable. When comparing a for and while loop, programmers check that they repeat the same number of times, update variables the same way, and produce the same output.

    Essential Knowledge 2.5.9. 2.5.B.6.

    Some conditional statements can be rewritten as equivalent Boolean expressions, and some Boolean expressions can be rewritten as equivalent conditional statements, without changing the program’s behavior.
    🔗
    🔗

    Activity 2.5.11.

    Which Boolean expression is equivalent to the following conditional statement?
    🔗
    if x < 5:
    small = True
else:
    small = False
    • small = x > 0
    • No. This expression is true for all positive values of x, but the original conditional statement is only true for values less than 5.
    • small = not x >= 5
    • Correct! An expression is equivalent if it always produces the same result. The expression not (x >= 5) is true exactly when x < 5.
    • small = not x > 5
    • No. This expression is true for values less than or equal to 5, but the original conditional statement is true for values less than 5.
    • small = x <= 5
    • No. This expression is true if x = 5, but the original conditional statement is false if x = 5.
    🔗

    Essential Knowledge 2.5.10. 2.5.B.3.

    A side effect occurs when an algorithm changes the program’s state while it runs. For example, an algorithm may update a variable’s value, add or remove an item from stored data, or change what the user sees on the screen.
    🔗
    🔗

    Essential Knowledge 2.5.11. 2.5.B.2.

    When comparing algorithms, programmers consider both the output and any side effects.
    🔗
    🔗
    Sometimes two algorithms may produce the same output but have different side effects. Side effects are anything an algorithm changes besides producing its main output, for example changing a variable’s value or changing something on the screen.
    🔗

    Activity 2.5.12.

    Given the two algorithms below, do they have the same outputs and side effects?
    🔗
    # Algorithm A
for i in range(3):
    print("Hello")

# Algorithm B
count = 1
while count <= 3:
    print("Hello")
    count += 1
    • Same outputs and same side effects
    • No, the algorithms update different variables, which is a side effect.
    • Same outputs and different side effects
    • Yes, the two algorithms produce the same output (printing "Hello" 3 times) but have different side effects (Algorithm A updates variable i from 0 to 2, while Algorithm B updates the variable count) from 1 to 3.
    • Different outputs and different side effects
    • No, both algorithms produce the same output (printing "Hello" 3 times).
    • Different outputs and same side effects
    • No, both algorithms produce the same output (printing "Hello" 3 times).
    🔗

    Essential Knowledge 2.5.12. 2.5.B.4.

    Side effects can impact the user experience. An unintended side effect, such as an incorrect variable update, an unexpected screen change, or an inconsistent program state, can confuse or frustrate users.
    🔗
    🔗
    Sometimes side effects are unintended and can cause problems. For example, if you are playing a game and finish a level, and you notice that your score was reset to 0 in the next level, that may be an unintended side effect or bad design.
    🔗

    Activity 2.5.13.

    The following two algorithms produce the same output. Which line of code is a side effect that one of the algorithms has that the other does not?
    🔗
    # Algorithm A
level = 1
score = 10
if score < 10:
   level = 1
else:
   level = 2
print("You've reached level", level)

# Algorithm B
level = 1
score = 10
if score >= 10:
   level = 2
   score = 0
print("You've reached level", level)
    • level = 2
    • No. Both algorithms change level to 2 when score is 10, even though the boolean conditions are different.
    • score = 0
    • Yes. Algorithm B changes score to 0 in the if-statement. This is a side effect of Algorithm B. Algorithm A does not change score.
    • if score >= 10:
    • No. The algorithms use different boolean conditions, but the results are the same.
    • else:
    • No. Only one algorithm uses an else statement, but that is not a side effect because it does not change a variable or the program’s state.
    🔗

    Essential Knowledge 2.5.13. 2.5.B.5.

    Algorithms that look similar may behave differently with certain inputs or may produce different side effects. To determine whether two algorithms are equivalent, programmers compare their outputs and side effects using the same inputs, often by tracing the steps and tracking changes to variables and displayed output.

    Subsection 2.5.4 Coding Challenge: Guessing Game

    In the following coding challenge, you will code a guessing game where the computer picks a random number from 0-100 and the user has to guess it. After each guess, the computer will give clues like “Too high” or “Too low”. We encourage you to work in pairs on this challenge.
    🔗
    Before you start coding, play the guessing game a few times in pairs. One student should play the part of the computer and think of a random number between 0 and 100. The other student should try to guess the number. After each guess, the student playing the computer should give clues like “Too high” or “Too low” until the correct number is guessed. Count the number of guesses you took. Switch roles and play again.
    🔗
    What is a good guessing strategy for guessing a number between 0 and 100? What was your first guess? One great strategy is to always split the guessing space into two and eliminating half, so guessing 50 for the first guess. This is called a divide and conquer or binary search algorithm because it divides the search space in half with each guess. If your guess is between 0-100, you should be able to guess the number within 7 guesses.

      Find the words in the lesson above and try again.
    • sequencing
    • ordering instructions one after another
    • iteration
    • repetition of a sequence of instructions
    • selection
    • choosing which statements to execute based on certain conditions
    • algorithm
    • a step-by-step procedure for solving a problem
    • accumulator pattern
    • a loop with a variable that accumulates a sum or total
    • average
    • the sum of a set of numbers divided by the size of the set
    • minimum
    • the smallest value in a set of numbers
    • maximum
    • the largest value in a set of numbers
    • side effect
    • a change other than the output to the program’s state or variables when the program runs
    • divide and conquer pattern
    • an algorithm that divides the problem into smaller parts and solves each part
